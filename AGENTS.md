# AGENTS.md — инструкция для ИИ-агента

Ты работаешь над проектом **football-analyzer** — коммерческим Telegram-ботом,
который круглосуточно следит за расписанием футбольных матчей и присылает
подписчикам математические прогнозы **за 5 часов до начала матча**.

Читай этот файл перед каждой задачей. Если чего-то нет в проекте — не выдумывай,
а спроси.

---

## 1. Продукт

- Бот работает 24/7, сам проверяет расписание, сам отправляет прогнозы.
- Прогноз — **математический**, считается локально. Никакой «генерации текста
  моделью».
- Целевая аудитория: пользователи Telegram, интересующиеся спортивной аналитикой.
- Продукт коммерческий → **деньги считаем** (см. раздел 5).

Что значит «готово» для первой версии (уточняется, см. раздел 10):

- [ ] бот запускается и отвечает на `/start`
- [ ] расписание матчей подтягивается из источника и сохраняется в базу
- [ ] прогноз считается локально (scipy, распределение Пуассона)
- [ ] за 5 часов до матча прогноз уходит подписчикам
- [ ] падение внешнего API не роняет бота
- [ ] повторный запуск не дублирует отправленные прогнозы

### Источники данных — что проверено на живых данных (30.10.2026)

| Источник | Что даёт | Состояние |
|---|---|---|
| ESPN (`site.api.espn.com`) | расписание матчей | ✅ **основной для расписания**: открытый JSON-API, без браузера, бесплатно |
| `soccerdata` (пакет) | обёртка над ESPN, FBref, Sofascore, Understat | ✅ установлен, версия 2026.43.0 |
| ESPN summary (`/summary?event=ID`) | **углы, ЖК, фолы, удары, владение по каждой команде** | ✅ проверено 06.11.2026: 17 из 17 соревнований с завершёнными матчами |
| FBref | статистика матчей | ⚠️ только через Chrome/Selenium: обычный HTTP отдаёт 403 (Cloudflare). **Нам не нужен** |

**Ограничение `soccerdata`, которое надо помнить.** «Из коробки» в нём всего
**8 соревнований**: топ-5 лиг (АПЛ, Ла-Лига, Серия A, Бундеслига, Лига 1) и три
турнира сборных. Наш список из 20 соревнований туда не влезает — расширять надо
через собственный `league_dict.json`. Поэтому расписание берётся **узким окном
напрямую из API ESPN** (тот же эндпоинт, что использует `soccerdata`), а не через
`ESPN.read_schedule()`: тот выгружает весь сезон — по календарю это ~80 дат на
лигу, то есть около **1600 запросов** на один проход по 20 соревнованиям.

Проверено: `scripts/check_sources.py` — 20 ключей ESPN, 19 вернули матчи;
«Отбор ЧМ (УЕФА)» найден, но матчей в окне нет (европейский отбор к ЧМ-2026
завершён). `python -m football_analyzer.cli fetch-schedule --days 3` — 132 матча,
83 запроса, 0 ошибок; окно с серединой недели — 193 матча, 127 запросов, 0 ошибок.

### Что мы сознательно НЕ используем

- **Платные LLM API для генерации текста.** Бюджет ограничен; прогноз —
  это математика, а не творчество. Вызовов Polza/OpenAI в этом проекте быть не
  должно. Если задача требует платного API — сначала согласование (раздел 5).
- **Блокировку в памяти процесса** для долгих операций (раздел 6).
- **Ручное копирование файлов на сервер** (раздел 7).

## 5. Деньги — главное правило

1. **Считать ДО, а не после.** Перед любой платной операцией назвать заказчику:
   сколько запросов уйдёт, сколько это рублей, что произойдёт при сбое.
   Запуск — **только после явного «да»**.
2. **Никогда** не запускать платное «чтобы проверить, работает ли». Проверка
   кода, типов, сборки и текстов — бесплатна.
3. **Знать норму** на единицу продукта. Больше нормы — признак утечки, а не норма.
4. **После запуска сверить факт с планом** по базе или логам. Разошлось —
   остановиться и разобраться, а не запускать снова.
5. **Доказательство — строка в базе**, а не `console.log('готово')` / `print('ok')`.
6. Если внешний сервис не успел в таймаут — **не выбрасывать результат**:
   сохранить id операции и опросить позже. Выбрасывание = повторная покупка.

Инструмент: `scripts/cost_guard.py` (+ `config/prices.json`).

```bash
python3 scripts/cost_guard.py plan polza.text.chat 100   # сколько будет стоить
python3 scripts/cost_guard.py record ... --key <id>      # факт в реестр
python3 scripts/cost_guard.py report --since 2026-10-01  # план/факт
```

Если цена операции не задана в `prices.json`, скрипт **отказывается считать**
(код выхода 2) — это защита, а не баг.

## 6. Надёжность

- **Блокировка в памяти процесса не защищает.** `set()`/`dict` внутри процесса
  не спасут от параллельного прохода или перезапуска. Долгая операция,
  тратящая деньги или делающая внешние вызовы, обязана быть под **арендой в
  базе** (`lease_until`), и аренда должна **истекать сама**.
- **Идемпотентность отправки.** Один матч → один прогноз → одна запись в журнал
  отправки. Перезапуск бота не должен слать прогноз повторно.
- **Внешние API падают.** Источники расписания и погодный API — оборачивать в
  таймауты и ретраи с backoff; ошибка источника не должна останавливать
  планировщик.
- **🔴 Ловушка ESPN, проверено на практике 30.10.2026.** Источник умеет отдавать
  **HTTP 200 с пустым списком матчей** вместо ошибки (похоже на троттлинг).
  Один проход в широком окне вернул 185 матчей вместо 193, и у АПЛ — 2 матча
  вместо 10, без единой ошибки в ответе. Молча потерять матч нельзя, поэтому:
  календарь соревнования говорит, в какие дни матчи вообще бывают; в игровой
  день пустой ответ повторяется до 3 раз, и если матчей нет — это пишется в
  `errors`, а не проглатывается. **Для отправки прогноза недостаточно одного
  прохода:** матч должен подтвердиться минимум в двух проходах подряд, иначе
  есть риск отправить прогноз по неполному расписанию.
- **Никогда не глотать исключения молча.** Логировать с контекстом: матч, лига,
  дата, источник.
- Все даты и время — в **UTC** внутри кода, в зоне пользователя — только при
  форматировании. Матчи в разных часовых поясах — классический источник багов.

## 7. Деплой

1. Сначала **стейдж**, прод — по отдельной команде.
2. Перед деплоем — **git tag** для отката: `git tag deploy-$(date +%F-%H%M)`.
3. Файлы на сервер — **только через git**. Скопированный руками файл блокирует
   `git pull` и ломает следующий деплой.
4. Деплой стейджа (с машины разработчика):

```bash
git push origin main
ssh -i ~/.ssh/football_analyzer_deploy root@168.113.176.166 'bash /root/provision.sh'
```

`provision.sh` идемпотентен: делает `git fetch && reset --hard origin/main`,
переустанавливает пакет, обновляет юниты. Firewall он тоже приводит к
«только SSH» — если добавляли свои правила, они затрутся.
5. После деплоя проверить **факт**, а не «запустилось»:

```bash
ssh ... 'systemctl list-timers football-analyzer-sync.timer --no-pager'
ssh ... 'sudo -u postgres psql -d football -c "select count(*) from matches;"'
ssh ... 'journalctl -u football-analyzer-sync -n 30 --no-pager'
```

6. Миграции — только аддитивные (см. раздел 4).
