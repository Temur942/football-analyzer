# Туннель до Telegram: сервер в РФ + маленький зарубежный узел

## Зачем

С российского хостинга недоступны адреса Telegram (проверено: 443 и 80 закрыты
ко всем диапазонам `149.154.*`, `91.108.*`, при этом Google, PyPI и Open-Meteo
открыты). Боту нужен выход к `api.telegram.org`, иначе он не может ни получать
сообщения, ни отправлять прогнозы.

## Почему не «переехать целиком»

По 152-ФЗ данные российских граждан должны храниться в базах **на территории
РФ** (ч. 5 ст. 18). Если унести базу с `telegram_id` и подписками в Нидерланды —
это прямое нарушение локализации. Поэтому:

```
[Сервер в РФ]  бот, PostgreSQL, прогнозы, персональные данные
      │  WireGuard, только адреса Telegram
      ▼
[Узел за границей]  ретранслятор: ничего не хранит, только NAT
      │
      ▼
  api.telegram.org
```

За границу уходит **только шифрованный трафик**, база остаётся в РФ.

## Что нужно купить

| Параметр | Минимум |
|---|---|
| CPU / RAM | 1 vCPU / 256 МБ (512 МБ комфортнее) |
| Диск | 5 ГБ |
| Трафик | 100 ГБ/мес (реально нужно 1–3 ГБ) |
| ОС | Ubuntu 24.04 или Debian 12 |
| Порт | UDP 51820 разрешён |
| Локация | Нидерланды / Германия / Финляндия — вне РФ |

Домен, SSL, панель и база не нужны.

## Порядок

### 1. На зарубежном узле (под root)

```bash
bash setup-node.sh
```

Скрипт выведет **публичный ключ узла** и адрес `<IP>:51820`.

### 2. На сервере в РФ (под root)

```bash
bash setup-client.sh <IP_УЗЛА> <ПУБЛИЧНЫЙ_КЛЮЧ_УЗЛА>
```

Скрипт выведет **публичный ключ клиента**.

### 3. Снова на узле — добавить клиента

```bash
bash setup-node.sh <ПУБЛИЧНЫЙ_КЛЮЧ_КЛИЕНТА>
```

### 4. Проверка (обязательно)

```bash
# Telegram должен ответить непустым HTTP-кодом
curl -s -m 15 -o /dev/null -w '%{http_code}\n' https://api.telegram.org/

# Маршруты: Telegram — через туннель, остальное — напрямую
ip route get 149.154.166.110    # → dev wg0
ip route get 142.250.74.46      # → dev ens3 (или ваш основной интерфейс)

# Туннель живой
wg show
```

И только после этого — запуск бота:

```bash
systemctl start football-analyzer-stage
journalctl -u football-analyzer-stage -n 30 --no-pager
```

## Что уходит через туннель

Только официальные диапазоны Telegram:

```
149.154.160.0/20
91.108.4.0/22
91.108.8.0/22
91.108.12.0/22
91.108.16.0/22
91.108.56.0/22
```

ESPN, Open-Meteo, GitHub и остальное идут напрямую — узел не нужен для них и не
нагружается.

## Откат

```bash
systemctl disable --now wg-quick@wg0
```

Трафик вернётся в обычное состояние; бот при этом перестанет работать (Telegram
снова недоступен) — это ожидаемо.

## Ограничения и риски

- **Узел — точка отказа.** Упал узел — бот не работает. Лечится мониторингом и
  быстрой заменой (настройка занимает минуты).
- **Список адресов Telegram может измениться.** Тогда бот перестанет получать
  сообщения, хотя сеть будет «в порядке». Диагностика: `ip route get` и `wg show`.
- **Узел видит только шифрованный трафик** (TLS до Telegram), содержимое ему
  недоступно.
- Юридическую часть (согласие на обработку, уведомление в Роскомнадзор) это
  решение **не отменяет** — данные всё равно уходят в Telegram, зарубежный
  сервис. Нужен юрист.
